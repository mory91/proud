# Pull Request Overview

Review the description, changed files, commits, checks, and conversation in one Vim-native surface. The details pane keeps two columns of horizontal inner padding on both sides, so text, separators, and native cards begin and end away from the pane edges. Long titles, metadata, and description text use the shared `ui.content_lines` capability. Wrapped content fits the constrained content box, while non-wrapped content retains the complete padded line for native horizontal navigation instead of being truncated. The capability follows Neovim's global `wrap` setting unless explicitly overridden. Once a reusable credential is resolved, the complete two-pane workspace appears immediately with loading content, then replaces that content in place when GitHub API data arrives. Credential access validation continues in the background instead of delaying the scene. Reviewers, labels, the description, and conversation are populated from GitHub API data rather than display fixtures. Overview sections use muted-grey separator rows. Conversation entries use reusable native Neovim rounded floating windows: root cards blend into the overview background, replies receive only a subtle grey shade, and each card combines author, review or comment metadata, and relative age in its header before the message. Review summary bodies and inline review comments both render; when a review summary is empty, its linked review messages appear as threaded cards beneath the review. GitHub reply links render as narrower indented cards beneath their parent. File viewed state is tracked independently so reviewers can resume work without rereading completed files. `<CR>` or `d` on a file opens the pull request's diff page (the compare page) on that file; `<CR>` on a commit opens it on that commit's change. `<leader>e` hides or shows the sidebar.

## Related Code

- `feature.lua` normalizes pull request details, tracks viewed files, and composes the overview.
- `features/conversation_cards/feature.lua` provides the reusable native card component used for the conversation section.
- `tests/unit_spec.lua` verifies symmetric overview padding for wrapped and non-wrapped content, file-state, grey separators, conversation metadata, nested replies, semantic colors, and fixed-width rendering across terminal sizes.
- `tests/e2e_spec.lua` verifies the viewed-file keyboard workflow, overview-to-diff navigation, delayed provider hydration, native card rendering, and stale-safe placeholder rendering.
- `bench/benchmark.lua` covers 200 changed files and 250 description lines.
- `tests/memory_leak_spec.lua` verifies repeated real-screen open/close lifecycle remains within the feature's memory and resource SLA.
