# Pull Request Browser

Find and open the right pull request without leaving Neovim. Above the browser, a non-focusable source selector provides `Review requested`, `Mine`, `All open`, `Recently viewed`, and `Branches`. `All open` is selected initially. Buttons use the UI framework's default borderless style: the active source has a purple background with white text, while inactive sources share the normal UI background with muted text. The selector is a native one-row floating strip with visible space above it and outside the rounded windows, and supports configurable next/previous actions, default `<Tab>` and `<S-Tab>`, without displaying key hints. Moving through sources updates the editable PR query and reloads its list.

The browser itself opens two native Neovim floating windows with rounded borders and no native titles: a list window and a live preview window. Each floating window reserves a native two-row top section strictly inside its border: the first interior row is the header and the second is a full-width grey separator, leaving the rounded top edge unobstructed. The list header is an editable `PR > ...` filter prompt with a right-aligned `filtered/total` count, and the preview header is a muted grey `Preview` label. The body reserves those rows on every render so content never slides beneath the header. The preview is focusable: a configurable action places a visible purple cursor on its first content row after the header, ordinary Neovim motions and scrolling explore the complete text, and a configurable action returns to the PR list. The rounded-window framework reacts to `VimResized`, recomputes both pane geometries, the in-window headers and separators, the outside source selector, and content widths without reopening the scene. It supports both terminal growth and shrink while preserving margins, gap, straight rows, and clear tabline/statusline space. The initial GitHub request is limited to complete two-row items visible in the list window, calculated from its live content height. Once selection movement begins, the browser keeps two additional GraphQL cursor pages prefetched ahead of the selected page and appends only unseen pull requests. Descriptions are absent from list payloads: the preselected first pull request is fetched immediately, subsequent cursor-selected descriptions are fetched after a configurable debounce, and loaded first messages are reused. Holding a movement key therefore does not fetch every intermediate description. The filtered count updates immediately with local filtering while the total remains the number of source pull requests. Filter edits are sent to GitHub only after a debounce window. Each pull request title and metadata subtitle occupy adjacent rows. Subtitles use `name · age · +additions-deletions · thread count · review state`, with compact relative ages such as `24m`, `1h`, `1d`, and `1w`, and thread labels such as `1 thread`, `2 threads`, or `no threads`. The preview uses GitHub-provided reviewer decisions, requests, exact label names, and the complete first message of the pull request: its original description. No Summary section is synthesized, and long descriptions scroll while PR selection remains on the list. Window margins and the gap between panes are configurable through `setup({ ui = { windows = ... } })`, and border-aware sizing follows the active Neovim chrome settings while keeping both cards clear of tablines and statuslines. It supports combined free-text, author, label, and state queries; keyboard navigation; configurable description scrolling; and direct actions for opening, checking out, and comparing pull requests.

## Related Code

- `feature.lua` contains source queries, viewport pagination, debounced on-demand descriptions, filtering, source/filtered counts, selection state, native rounded-window setup, semantic row styling, and buffer-local mappings.
- `tests/unit_spec.lua` verifies page sizing, cursor append semantics, lazy description states, source query mapping and selector colors, query semantics, `8/14` count formatting, source-count preservation, API metadata, selection bounds, row metadata, and fixed-width rendering.
- `tests/e2e_spec.lua` drives selection, held-movement description debouncing, cursor-page loading, source selector navigation and reloads, open behavior, dynamic header counts, and the two native windows in Neovim.
- `bench/benchmark.lua` verifies visible-page opening with source-selector layout, two-page cursor prefetch from a 500-pull-request backlog, retained-page rendering, filter, description, and source-query debounce cancellation, filtering, and count-update costs.
- `tests/memory_leak_spec.lua` verifies repeated real-screen open/close lifecycle remains within the feature's memory and resource SLA.
